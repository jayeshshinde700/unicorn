2. Room Search and Availability Checking

Availability is determined dynamically by comparing room inventory in rooms.data against active booked spans in MySQL.

The Overlap Interval Formula: 
SELECT COUNT(*) FROM bookings
WHERE room_id = :room 
  AND check_in < :requested_checkout 
  AND check_out > :requested_checkin
  AND (booking_status = 'confirmed' 
       OR (booking_status = 'pending' AND hold_expires_at > NOW()))
Available rooms = MAX(0, room.inventory - booked_count). If available < 1, reason = 'soldout'. If total guests > room.guests, reason = 'capacity'.

MySQL Schema Table Blueprint

CREATE TABLE `bookings` (
  `id` INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `booking_id` VARCHAR(20) NOT NULL,                    -- Prefix 'UCH-' + 8 random crypto chars
  `request_token` CHAR(32) NULL,                         -- 128-bit hex token for idempotency
  `room_id` VARCHAR(40) NOT NULL,                        -- FK to rooms(id)
  `room_name` VARCHAR(60) NOT NULL,
  `guest_first_name` VARCHAR(60) NOT NULL,
  `guest_last_name` VARCHAR(60) NOT NULL,
  `email` VARCHAR(190) NOT NULL,
  `phone_country` VARCHAR(8) NOT NULL DEFAULT '+91',
  `phone` VARCHAR(20) NOT NULL,
  `check_in` DATE NOT NULL,
  `check_out` DATE NOT NULL,
  `adults` TINYINT UNSIGNED NOT NULL DEFAULT 1,
  `children` TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `number_of_nights` SMALLINT UNSIGNED NOT NULL,
  `price_per_night` DECIMAL(10,2) NOT NULL,              -- Snapshot of rate at booking time
  `subtotal` DECIMAL(12,2) NOT NULL,
  `tax_percent` DECIMAL(5,2) NOT NULL DEFAULT 0.00,
  `tax_amount` DECIMAL(12,2) NOT NULL DEFAULT 0.00,
  `total_amount` DECIMAL(12,2) NOT NULL,
  `special_requests` TEXT NULL,
  `booking_status` ENUM('pending','confirmed','cancelled') NOT NULL DEFAULT 'confirmed',
  `hold_expires_at` DATETIME NULL,
  `email_status` VARCHAR(12) NOT NULL DEFAULT 'pending', -- 'sent' | 'failed' | 'disabled'
  `created_at` DATETIME NOT NULL,
  `updated_at` DATETIME NOT NULL,
  `cancelled_at` DATETIME NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uq_booking_id` (`booking_id`),
  UNIQUE KEY `uq_request_token` (`request_token`),
  KEY `idx_room_dates` (`room_id`, `check_in`, `check_out`),
  CONSTRAINT `fk_bookings_room` FOREIGN KEY (`room_id`) REFERENCES `rooms` (`id`)

Signed HMAC-SHA256 Access Tokens

To prevent unauthorized tampering or guessing of reservation details, the system generates cryptographically signed tokens stored in sessionStorage. 

// HMAC Token Format (api/lib/booking-functions.php)
$payload = base64_url_encode($bookingId . '|' . $exp);
$token = $payload . '.' . hash_hmac('sha256', $payload, $secret);

// Timing-safe verification:
hash_equals(hash_hmac('sha256', $parts[0], $secret), $parts[1]);
Tokens expire in 30 minutes (access_token_minutes) and protect against ID enumeration in download.php and calendar.php.

Concurrency & Double-Booking Prevention

When two guests attempt to book the last available suite at the exact same millisecond:

Guest A (First Millisecond):

Enters transaction. Obtains SELECT ... FOR UPDATE lock on room row. Checks availability: 1 available. Executes insert into bookings. Commits. Lock released. Returns 201 Created.

Guest B (Second Millisecond):

Enters transaction. Blocked on FOR UPDATE lock until Guest A finishes. Lock acquired: re-evaluates count. Available is now 0. Aborts with rollBack() and returns 409 Conflict: "The selected room is no longer available for these dates."
